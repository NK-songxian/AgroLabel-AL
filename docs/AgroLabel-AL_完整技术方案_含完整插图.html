AgroLabel-AL 完整技术方案（导师审核稿）

本文完整整理前两轮关于赛题一的方案回答，保留原有技术路线、模块设计、公式、实验建议、数据集说明和实施计划。文中的示意性实验数值仅用于说明展示方式，不代表真实实验结果。

第一部分：赛题一分析与高分方案

一、先分析赛题一：评委究竟想要什么？

赛题一的名称是：

面向智慧农业场景的多模态数据智能预标注与主动学习原型系统。

赛题文件第3～6页明确提出了四项核心任务：

  1. 选择具体农业场景，完成问题定义。
  2. 使用本地部署模型进行自动预标注。
  3. 设计主动学习策略，自动筛选最值得人工标注的困难样本。
  4. 实现导入、预标注、人工修改、数据回流和提效统计的完整系统。

赛题一评分结构

总分100分：

评分维度 分值 评分要点
预标注质量 30 目标类别预标注精度与可用性18分；细分类别/小样本表现12分
主动学习有效性 25 难例筛选策略合理性12分；同等质量下人工标注量下降的实测消融13分
人机协同原型完整度 25 预标—修正—回流闭环可演示15分；提效指标量化与统计可信度10分
工程实现与可复现性 15 代码质量与运行稳定性8分；可复现与文档完备7分
展示与合规 5 报告与演示表达3分；数据脱敏与本地推理合规意识2分

关键判断：95分来自算法、主动学习、系统和工程，而不是单纯的模型精度。

这意味着：

  • 只训练一个 YOLO 模型：不够。
  • 只做一个 SAM 自动分割工具：不够。
  • 只做一个漂亮的网页：不够。
  • 有主动学习，但没有随机采样对照实验：不够。
  • 有模型、有算法、有可交互系统、有真实提效数据：才有竞争力。

建议按照冲击一等奖甚至特别奖的标准设计，而不是按照完成基本要求设计。

二、项目定位：选择什么农业场景？

推荐优先选择：

农作物病害智能检测与病斑实例分割

具体任务： 对农业图像中的作物病害进行自动检测，识别病害类别，并对不规则病斑区域进行分割。

选择理由：

  • 病斑大小差异明显，适合研究小目标识别。
  • 病害类别存在细粒度差异，适合小样本学习。
  • 病斑边界不规则，适合设计分割算法。
  • 不同病害类别样本数量不均衡，适合主动学习。
  • 能够直观展示 AI 预标注和人工纠错效果。

注意：这是推荐的研究场景，不是赛题文件已经确认提供的具体数据类别。企业只承诺提供脱敏农业/作物图像及标注规范样例，PlantVillage 等公开数据可以补充。最终必须先检查企业样本，再确定病害类别和标注形式。

如果企业提供的主要是分类标签或检测框，而不是病斑掩码，可以将主任务调整为目标检测，不能为了创新强行制造不可靠的分割标签。

三、核心方案：AgroLabel-AL

面向智慧农业的多模态智能预标注与价值感知主动学习系统

整个系统采用四层架构：

  1. 第一层：多模态农业数据输入——RGB图像 + 病害类别语义描述 + 可选农情元数据。
  2. 第二层：智能预标注模型——视觉特征提取 + 小病斑检测 + 语义先验融合 + 实例分割。
  3. 第三层：价值感知主动学习——不确定性 + 多样性 + 稀有类别 + 标注成本。
  4. 第四层：人机协同标注平台——人工修正 + 质量检测 + 数据回流 + 增量训练。

持续迭代，形成数据闭环。

四、三个核心算法创新

创新一：语义先验引导的多模态小样本预标注网络

普通 YOLO 模型主要依赖图像视觉特征。但农业场景存在几个问题：

  • 同一种病害在不同生长阶段外观不同。
  • 不同病害可能具有相似的颜色和纹理。
  • 小样本类别难以学到稳定的特征。
  • 小病斑容易被背景和叶片纹理干扰。

建议以轻量级 YOLO 实例分割模型为基础，构建三个创新模块。

1. 模型结构

模块 功能 解决的问题
MSF-Encoder 多尺度高分辨率特征提取 微小病斑漏检
CSPF Module 作物语义先验融合 细粒度类别混淆
BBR-Head 病斑边界感知分割头 病斑边界不准确

2. MSF-Encoder：多尺度病斑特征提取

建议在 YOLO 主干网络中增加 P2 高分辨率检测分支，同时使用轻量级多尺度特征融合：

  • 浅层：保留病斑纹理、颜色、边缘。
  • 中层：识别病斑形态。
  • 深层：学习病害整体语义。

重点是提高小病斑的召回率。

3. CSPF：作物语义先验融合模块

输入不再只有 RGB 图像，还包括：

  • 图像视觉特征。
  • 病害类别名称。
  • 病害症状描述。
  • 可用时的作物品种、生长阶段等元数据。

例如，图像特征为“叶片局部存在褐色不规则斑点”，文本先验为“番茄早疫病：褐色病斑，可能呈同心轮纹”。

将视觉特征和文本类别原型映射到同一语义空间，利用门控交互进行融合。这样模型不仅观察图像，还可以利用病害类别的语义信息。

如果企业没有提供生长阶段等元数据，就不依赖这一分支，确保系统能够在纯图像条件下运行。

4. BBR-Head：边界感知分割头

同时预测：

  • 病害类别。
  • 病斑检测框。
  • 病斑实例掩码。
  • 病斑边界信息。

建议损失函数：

[ L=L_{det}+1L{Dice} +2L{Boundary} +3L{Proto} ]

其中：

  • (L_{det})：检测分类和定位损失。
  • (L_{Dice})：病斑分割损失。
  • (L_{Boundary})：边界约束损失。
  • (L_{Proto})：小样本类别原型对比损失。

这一创新的价值：不只是使用现成模型进行预标注，而是针对小病斑、细粒度病害和不规则边界进行专门优化。

创新二：不确定性—多样性—稀有类别联合主动学习

这是整个比赛最关键的算法之一。

赛题明确要求系统能够判断哪些图片最值得人工标注，并与随机采样进行对照验证。

普通主动学习经常只使用模型置信度。建议设计：

VARD-AL：价值感知的稀有类别主动学习算法。

1. 四种样本价值

① 不确定性 U

模型预测置信度低、类别概率接近、分割边界不稳定。

② 样本多样性 D

优先挑选与已有训练样本差异较大的图片，避免重复标注。

③ 类别稀缺性 R

对数量少、模型识别困难的病害类别给予更高优先级。

④ 模型分歧 G

通过不同增强视图或教师—学生模型预测差异，发现潜在难例。

2. 联合采样公式

[ S_i= ]

其中：

符号 含义
U 模型不确定性
D 样本特征多样性
R 类别稀缺程度
G 模型预测分歧
C 预计人工标注成本
α、β、γ、δ 权重参数

这里最值得强调的是 (C_i)。

例如，一张图只有一个简单病斑；一张图有十几个不规则病斑；一张图存在严重遮挡，需要大量人工修正。它们的人工成本明显不同。

因此，不应该只选择最困难的图片，而应该优先选择单位人工标注成本能够带来最大模型提升的图片。

3. 主动学习执行流程

  1. 模型预测全部未标注图片，输出类别、检测框、分割掩码和置信度。
  2. 计算四维样本价值：不确定性、多样性、稀有类别和模型分歧。
  3. 根据人工标注成本计算最终优先级。
  4. 选择 Top-K 图片，优先进入人工标注工作台。
  5. 人工修正并回流，将修正结果加入训练集，执行增量微调。

4. 必须做的对比实验

方法 采样策略
Baseline 随机采样
AL-1 仅不确定性
AL-2 不确定性 + 多样性
AL-3 不确定性 + 稀有类别
Ours 四维联合 + 标注成本

重点展示：

  • 同样标注100张图片，哪种策略模型精度更高？
  • 达到相同精度，哪种策略需要人工标注的图片更少？
  • 少数类的识别精度是否提高？

这部分一定要有实测结果，不能只展示公式。

创新三：教师—学生协同的高效预标注与持续学习

我不建议直接用大型视觉模型对所有图片进行实时推理。

原因是赛题要求本地推理、单张图片预标注时延不高于300ms，并推荐 GPU 显存不低于8GB，但也允许轻量化模型运行。

建议使用教师—学生结构。

教师模型：

  • GroundingDINO：通过病害文本提示生成候选检测框。
  • SAM2 或轻量级 SAM：对候选区域进行掩码细化。
  • 教师模型主要负责初始伪标签生成和难例辅助修正，可以离线运行。

学生模型：

  • YOLO 轻量实例分割网络。
  • 蒸馏教师的检测、分类和掩码知识。
  • ONNX Runtime 部署。
  • INT8 量化优化。

最终用户日常使用轻量学生模型完成预标注。

持续学习机制：

  1. 保存人工修正标签。
  2. 记录修改前后的预测差异。
  3. 将高质量样本加入训练集。
  4. 按类别平衡策略抽样。
  5. 定期增量微调。
  6. 新旧模型进行验证后再切换版本。

这样系统不是一次性训练，而是一个不断进步的农业数据标注系统。

五、原型系统：必须做出什么功能？

建议做成一个本地部署的 Web 标注平台。

技术栈：

  • 前端：Vue3 + Canvas/Konva。
  • 后端：FastAPI。
  • 模型：PyTorch + ONNX Runtime。
  • 数据库：SQLite。
  • 可视化：ECharts。
  • 模型训练：PyTorch。

如果开发时间和人手不足，可以用 Gradio 快速搭建第一版，但正式展示尽量做成完整工作台。

六个核心页面

页面 核心功能
1. 数据管理 图片上传、批量导入、数据集管理
2. 智能预标注 自动检测、类别预测、掩码生成
3. 人工修正 拖动框、修改多边形、画笔修正、类别修改
4. 主动学习 难例排序、优先级、筛选原因
5. 数据质量 错误检测、重复标签、类别统计
6. 效率看板 标注耗时、修改次数、模型精度、节省比例

最重要的交互设计

用户上传一批图片后，系统自动完成预标注。每张图片显示：

  • 预测类别。
  • 预测置信度。
  • 检测框和病斑掩码。
  • 预测是否需要人工复核。

用户可以：

  • 接受全部预测。
  • 单独修改某个病斑。
  • 删除错误检测。
  • 手动画出漏检病斑。
  • 修改错误类别。
  • 保存最终标签。

最后导出 COCO 或 YOLO 格式。

这才真正满足企业所说的端到端闭环。

六、实验设计：怎样证明我们比别人强？

建议把实验分成四组。

1. 预标注模型实验

对比：

  • YOLO 基础模型。
  • YOLO + P2 小目标分支。
  • YOLO + 语义融合。
  • YOLO + 边界感知分割。
  • 完整 AgroLabel-AL。

评价指标：

指标 目的
Precision 预测准确程度
Recall 病斑检出能力
mAP50 检测性能
mAP50-95 综合检测性能
Mask mAP 实例分割性能
Dice / IoU 掩码质量
Macro-F1 少数类别表现

尤其要单独展示小病斑和稀有病害类别的结果。

2. 主动学习实验

设定人工标注预算为训练样本的5%、10%、20%、30%。比较随机采样和不同主动学习策略的表现。

正式参赛时必须用真实实验数据替换任何示意曲线。

3. 人机协同提效实验

设置两种工作方式：

  • A组：人工从零开始标注。
  • B组：AI预标注后人工修正。

对比单张标注耗时、人工修改操作次数、标签质量和单位时间标注量。

要求两组最终达到相同的质检质量。

4. 工程性能实验

必须测试：

  • 单张图片推理时间。
  • GPU 显存占用。
  • CPU 运行能力。
  • ONNX 与 PyTorch 精度差异。
  • INT8 量化前后速度和精度变化。
  • 连续批量导入是否稳定。

建议将比赛要求作为硬指标：人工修改次数下降不低于30%；达到同等质量所需人工标注量下降不低于20%；单张预标注推理时延不高于300毫秒。这些是企业给出的参考指标，不是已经取得的实验成绩。

七、真正冲高奖项，还需要增加什么？

增强方向 A：智能标注质量控制

在人工保存标签之前，自动检查：

  • 掩码是否越界。
  • 是否存在异常小目标。
  • 是否出现重复检测。
  • 是否存在类别冲突。
  • 掩码与检测框是否匹配。
  • 同一类别的标签是否符合规范。

对明显异常标签自动提示，不让错误标签进入训练集。

增强方向 B：标注行为驱动的模型优化

记录人工每次修改：

  • 删除了哪些错误预测？
  • 哪些位置经常漏检？
  • 哪些类别经常被改错？
  • 哪些区域需要反复调整？

进一步统计模型的系统性错误，形成错误类型分析报告。

例如，如果模型经常把叶片自然纹理识别为病斑，就增加对应负样本；如果小病斑漏检严重，就提高对应类别和尺度的训练权重。

这比简单的人工纠错更有创新价值。

十、最终判断：怎样的方案最有可能拿高分？

三个真正需要向评委讲清楚的创新：

  1. 模型创新：语义先验引导的多模态小样本病斑预标注网络。 解决农业图像中微小病斑、细粒度类别和不规则边界识别问题。
  2. 算法创新：不确定性—多样性—稀有类别—标注成本联合主动学习。 让系统自动寻找最值得人工标注的图片，降低标注成本。
  3. 系统创新：人工纠错驱动的持续学习与智能质量控制闭环。 实现自动标注、人工修改、质量检测、数据回流和模型更新。

不要向评委展示一个能够识别农作物病害的模型，而要展示一个能够自主发现标注难题、合理分配人工标注资源，并通过人工反馈持续提升标注质量的智能数据生产系统。

第二部分：AgroLabel-AL 完整可执行技术方案

一、项目最终定位与创新点

参赛条件：公开数据集；病害检测 + 病斑分割；1—2人团队。

先明确一个重要技术问题：

不能直接拿 PlantVillage 的分类标签训练病斑检测与分割模型。

PlantVillage 主要提供整张叶片的作物—病害类别标签，并没有原生的病斑级检测框和病斑像素掩码。它适合做病害分类预训练，但不能直接证明病斑定位和分割能力。

建议调整数据组合：

三类公开数据集，各司其职

数据集 定位 标签和用途 获取地址
PlantVillage 分类预训练 约54,000张图像、38个作物—病害类别；学习病害类别和视觉语义特征 https://data.mendeley.com/datasets/tywbtsjrjv/1
PlantSeg 核心检测与分割数据 11,458张图像、115种病害、34种寄主植物，包含病害区域掩码；可派生连通区域检测框 https://doi.org/10.5281/zenodo.17719108
PlantDoc 外部检测验证 2,346张图像、8,435个检测框、29个类别；用于检测能力和复杂场景泛化验证，不直接作为分割标签来源 https://huggingface.co/datasets/Project-AgML/plant_doc_detection

PlantSeg 原始论文：https://www.nature.com/articles/s41597-025-06513-4

这三个数据集形成：

  • PlantVillage：学会识别病害。
  • PlantSeg：学会定位和分割病斑。
  • PlantDoc：检验复杂场景下的检测能力。

PlantSeg 的优势是拥有真正的病害区域像素级标签，而且包含野外复杂背景；PlantDoc 可以补充检测任务。

建议最终项目定位：

AgroLabel-AL：面向智慧农业的病害多模态智能预标注与价值感知主动学习系统。

核心目标：自动检测病斑、分割病害区域、筛选最有价值的人工标注样本，并通过人工修正持续优化模型。

建议保留三个核心创新：

创新 技术名称 核心作用
创新一 HAFM 多尺度病斑增强融合 提高小病斑检测与分割能力
创新二 BAGS 边界感知几何监督 提高不规则病斑轮廓精度
创新三 VARD-AL 价值感知主动学习 降低人工标注成本

另外增加一个轻量级语义先验分支，将作物种类、病害类别及症状描述融合进视觉特征，体现多模态特点。

真正的创新不能只体现在模块名称上，需要通过模块消融、对照实验和标注效率实验验证每个模块的实际贡献。

3.2 模块一：HAFM 多尺度病斑增强融合

全称：High-resolution Adaptive Feature Modulation。

研究动机

病斑通常具有以下特点：

  • 小病斑面积占比低。
  • 不同病斑尺度差异大。
  • 病斑边缘与正常叶片纹理相似。
  • 深层特征可能丢失细小纹理。

传统检测网络在连续下采样过程中容易丢失小目标信息。

改进一：增加 P2 高分辨率检测分支

YOLO 常规检测主要使用 P3、P4、P5。这里增加 P2：

特征层 下采样倍数 作用
P2 4 微小病斑
P3 8 小型病斑
P4 16 中型病斑
P5 32 大型病斑

P2 的空间分辨率更高，可以保留更细的局部纹理。

改进二：高低层自适应融合

设浅层特征为 (F_2)，上采样后的深层特征为 (F_3)。

先通过通道映射：

[ F_2=Conv_{1}(F_2) ]

[ F_3=Up(Conv_{1}(F_3)) ]

计算融合门控：

[ G=(Conv_{1}([F_2,F_3])) ]

最终：

[ F_{HAFM}=GF_2+ (1-G)F_3 ]

再通过深度可分离卷积进行特征增强：

[ F’{HAFM}=PWConv(DWConv(F{HAFM})) ]

这样：

  • 浅层提供纹理细节。
  • 深层提供病害语义。
  • 门控机制自动决定不同特征的融合比例。

真正的创新点：不是简单增加一个P2检测头，而是设计病斑细节与高层语义之间的自适应融合机制。

建议消融：

  1. 原始 YOLOv8n-seg。
  2. YOLO + P2。
  3. YOLO + P2 + HAFM。

重点比较小目标 Recall、Mask AP 和推理速度。

3.3 模块二：BAGS 边界感知几何监督

全称：Boundary-Aware Geometric Supervision。

这个模块针对病斑边界不规则、分割结果容易虚胖或边缘缺失的问题。

研究动机

传统 Dice Loss 和 BCE Loss 主要优化区域重叠程度，但病斑的几何边界也很重要。

例如：

  • 两个面积相近的掩码，边界形状可能差异很大。
  • 微小病斑边缘偏移几个像素，就可能造成明显的区域误差。
  • 不规则病斑容易出现轮廓平滑过度的问题。

网络设计

在原始分割头旁边增加一个边界辅助预测分支。网络同时预测：

  1. 病斑掩码 (M)。
  2. 病斑边界图 (B)。
  3. 归一化有符号距离图 (D)。

其中：

  • (M)：病斑区域。
  • (B)：病斑边缘。
  • (D)：每个像素到病斑边界的有符号距离。

标签生成

利用真实掩码进行形态学处理：

[ B_{GT}=Dilate(M_{GT})-Erode(M_{GT}) ]

有符号距离图：

[ D_{GT}(p)=

]

再对距离值进行归一化，避免距离数值过大。

损失函数

区域损失：

[ L_{mask}=L_{BCE}+(1-Dice) ]

边界损失：

[ L_{boundary}=BCE(B,B_{GT}) +(1-Dice(B,B_{GT})) ]

距离约束：

[ L_{distance}=SmoothL1(D,D_{GT}) ]

最终：

[ L_{BAGS}= L_{mask} +b L{boundary} +d L{distance} ]

这样模型不仅要学会病斑在哪里，还要学会病斑边缘在哪里。

工程实现注意：边界分支在训练时增加监督，推理时可以移除辅助分支，只保留分割输出，从而降低部署成本。

3.4 模块三：语义原型引导的多模态融合

这是整个方案中体现多模态特征的部分。

为什么需要语义先验？

例如：

  • 番茄早疫病。
  • 番茄晚疫病。
  • 马铃薯早疫病。
  • 马铃薯晚疫病。

它们可能存在相似的颜色、纹理和病斑形态。只依赖局部图像纹理，容易发生细粒度类别混淆。

设计方案

使用冻结的 CLIP 文本编码器，在训练前生成疾病类别语义原型。

例如：

A close-up image of a tomato leaf
with early blight disease.

A close-up image of a tomato leaf
with late blight disease.

A close-up image of a potato leaf
with early blight disease.

每个类别生成文本向量：

[ T_c=E_{text}(Prompt_c) ]

视觉检测特征生成：

[ V_i=E_{visual}(F_i) ]

计算相似度：

[ S_{ic}= ]

其中 () 为温度参数。

最终分类分数融合：

[ Z_i=Z_i^{det}+_i S_i ]

其中 (_i) 由门控网络预测，并限制在合理范围内。

多模态损失

[ L_{semantic}=CE(Softmax(S_i),y_i) ]

如果类别之间存在明显语义相似性，还可以增加对比学习损失，但不建议第一版就引入复杂的对比学习框架。

特别注意：

  1. 文本原型在本地提前生成并缓存。
  2. 推理时不调用在线大模型。
  3. 不能将真实测试类别直接作为模型输入。
  4. 所有候选类别的文本原型都参与预测。
  5. 对于数据集之间无法统一的类别，不进行强制语义融合。

如果 CLIP 语义分支不能提升验证集性能，就应当移除，而不是为了保留多模态概念而强行使用。

五、核心算法：VARD-AL 价值感知主动学习

这是最应该重点投入的部分。

因为模型创新只能提高预标注质量，而主动学习直接解决企业最关心的问题：

有限人工标注预算下，怎样让模型尽可能快地变好？

传统随机标注：人工随机选取100张图片，逐张标注。

我们的方法：AI先分析全部未标注图片，找出最值得人工标注的100张。

5.1 四维价值评价机制

A. 不确定性 U

判断模型对当前图片是否有把握。包含三个部分：

  • 分类不确定性。
  • 检测框置信度不确定性。
  • 分割掩码不确定性。

分类熵：

[ U_{cls}= - _{c=1}^{C}p_c(p_c+) ]

检测不确定性：

[ U_{det}=1-_{j=1}^{N}conf_j ]

掩码不确定性：

[ U_{mask}= _{x,y}4p(x,y)(1-p(x,y)) ]

最终：

[ U=0.4U_{cls}+0.3U_{det}+0.3U_{mask} ]

其中掩码不确定性建议只在模型预测的病斑区域附近计算，避免大量背景像素稀释结果。

B. 多样性 D

避免人工反复标注相似图片。

利用 Backbone 的图像特征提取向量：

[ f_i=Encoder(I_i) ]

计算未标注图片与当前已标注集合的最小余弦距离：

[ D_i= _{jL} (1- {|f_i||f_j|}) ]

距离越大，说明图片越具有新颖性。

为了避免不同量纲影响，所有指标均进行归一化。

C. 稀有类别 R

如果模型发现某类病害样本非常少，就应该增加这类样本的标注优先级。

定义：

[ R_c= ]

其中 (n_c) 是当前训练集该类别的有效标注数量。

对于一张包含多个预测病斑的图片：

[ R_i=_{cP_i}R_c ]

这里 (P_i) 为该图片预测出的类别集合。

如果一张图片没有预测出病斑，则不凭空赋予某个稀有类别，而由不确定性和多样性分数处理。

D. 模型分歧 G

同一张图片在不同增强条件下预测不一致，可能存在复杂病斑。

具体做法：对一张图片执行：

  • 原图推理。
  • 水平翻转推理。
  • 轻微亮度变化推理。

将不同视图的检测框和掩码映射回原始坐标系，匹配相应预测，再计算预测差异。

例如：

[ G_i=1- (M_i{view1},M_i{view2}) ]

也可以加入类别预测分布之间的 Jensen-Shannon Divergence。

不需要额外训练第二个大型模型，使用测试时增强就可以实现。

5.2 增加人工标注成本感知

传统主动学习只考虑样本价值。但一张简单图片可能只需要5秒钟就能修正，一张复杂图片可能需要2分钟才能修正。

因此，增加人工标注成本 (C_i)。

建立初始标注成本模型：

[ C_i=a+bN_i+cP_i ]

其中：

  • (N_i)：预测病斑数量。
  • (P_i)：预测掩码的边界复杂度。
  • (a,b,c)：通过实际人工标注时间拟合的参数。

在平台运行初期，先记录50～100张图片的真实人工修正时间，建立初始成本估计模型，之后可以逐步更新。

5.4 多样性约束：防止选出100张相似图片

仅按照分数排序可能导致一个问题：模型发现100张番茄早疫病图片都很难，于是全部选出来。这不利于数据集的类别覆盖。

建议采用贪心批量选择：

  1. 先选择得分最高的图片。
  2. 计算其他图片与已选图片的特征距离。
  3. 优先选择高价值且与已选样本差异较大的图片。
  4. 同时设置类别数量上限或稀有类别最低配额。

可以使用：

[ Q_i=S_i+_{jB}d(f_i,f_j) ]

其中 (B) 为本轮已经选中的图片集合。

这样能兼顾价值与多样性。

5.5 主动学习完整执行流程

  1. 初始已标注训练集 L₀（5%）。
  2. 训练初始 AgroHAFM-Seg 模型。
  3. 对未标注池 U 进行预测。
  4. 计算 U、D、R、G、C。
  5. VARD-AL 价值排序与多样性筛选。
  6. 人工标注与修正。
  7. 新标签加入 L，训练集扩大。
  8. 进入下一轮主动学习。

5.6 必须完成的对照实验

方法 策略
Random 随机选择
Entropy-AL 仅不确定性
CoreSet-AL 仅多样性
Hybrid-AL 不确定性+多样性
VARD-AL 四维联合+成本感知

建议采用：

  • 初始标注预算：5%。
  • 每轮增加：5%。
  • 总预算：5%、10%、15%、20%、25%、30%。
  • 每个方法运行3个随机种子。
  • 验证集、测试集始终固定。

最终比较：

  1. 相同标注预算下的 mAP 和 mIoU。
  2. 达到相同模型精度所需的标注图片数量。
  3. 达到相同质量所需的人工时间。
  4. 稀有类别的检测和分割性能。

其中第三项特别重要，因为企业真正想减少的是人工工作量，而不只是减少图片数量。

七、训练与实验：具体怎么做？

7.1 第一组：模型对比实验

E5 E4 + Semantic 多模态语义

  • Box mAP50。
  • Box mAP50-95。
  • Mask mAP50。
  • Mask mAP50-95。
  • mIoU。

  • Boundary F1。

固定模型结构，只改变采样策略。

建议计算：

其中 (b) 为人工标注预算。

AULC 越大，说明相同标注预算下模型整体学习效率越高。

此外计算：

[ Saving= % ]

其中 (T) 是达到相同质量所需要的人工标注时间。

7.3 第三组：人机协同提效实验

建议抽取200张图片进行人工实验。

分为两组：

  • A组：纯人工标注。
  • B组：AI预标注后人工修正。

两组最终标签必须达到同等质量。

记录：

评价指标 A组 B组
平均每张图片耗时 实测 实测
每张图片修改次数 实测 实测
标签最终质量 实测 实测
每小时完成图片数 实测 实测

如果只有一名标注人员，建议采用交叉顺序测试：一部分图片先纯人工、一部分先AI辅助，再交换方式，减少人员熟练程度和图片难度带来的偏差。

如果有两名人员，可以采用相同难度分层的配对任务，并进行独立质量抽查。

不要把机器自动预测时间当成人工节省时间，也不要把模型置信度当成标签正确率。

7.4 第四组：跨数据集泛化实验

训练集：PlantSeg。

外部测试：PlantDoc。

但只对两个数据集类别和标注语义能够准确对应的部分进行比较。

检测框指标在 PlantDoc 上评价，分割指标在 PlantSeg 上评价，不要把没有分割标签的 PlantDoc 当作分割测试集。

另外建议专门测试：

  • 正常背景。
  • 复杂背景。
  • 光照变化。
  • 遮挡。
  • 小病斑。
  • 少数类别。

PlantVillage 的实验结果只能作为受控图像环境下的辅助结果，不能直接作为野外病斑检测泛化能力的证据。

  • 开启混合精度。

8.1 训练顺序

  1. 训练基础模型： YOLOv8n-seg + PlantSeg，建立可复现基线。
  2. 加入P2和HAFM： 观察小病斑检测是否提升。
  3. 加入BAGS： 观察 Dice、mIoU 和 Boundary F1 是否提升。
  4. 加入语义原型： 观察细粒度类别识别是否提升。
  5. 执行主动学习： 比较不同采样策略在相同标注预算下的效果。
  6. 导出部署模型： ONNX、FP16/INT8 量化，进行速度和精度测试。

8.2 速度优化

企业要求的参考时延是单张图片不超过300ms。

建议使用：

  • ONNX Runtime。
  • FP16 推理。
  • INT8 动态或静态量化测试。
  • 批量推理。
  • 模型剪枝（如果确实需要）。

注意：必须分别测量纯模型推理时间和完整系统处理时间。

建议预热50次，再测量至少500张图片，记录：

  • 平均时延。
  • 中位数时延。
  • P95时延。
  • FPS。
  • 显存占用。

报告中写明 CPU、GPU、显存、输入尺寸、推理精度和 batch size。

十一、项目风险与解决方案

风险 解决方案
PlantVillage没有病斑掩码 只用于分类预训练
PlantSeg连通区域不等于真实病斑实例 明确伪实例标签，抽样人工核验
多数据集类别不一致 建立统一类别映射，只合并确切对应的类别
CLIP语义分支没有提升 做独立消融，效果不好就移除
主动学习只提高模型精度但没有节省人工时间 必须记录真实标注耗时并进行等质量对照

另外，PlantVillage主要是受控环境图像，PlantSeg和PlantDoc更接近复杂自然场景。不能只在 PlantVillage 上获得高分类准确率，就宣称已经解决了野外病斑识别问题。

十三、最终确定的技术路线

AgroLabel-AL 最终项目技术架构：

第一部分：数据层

PlantVillage + PlantSeg + PlantDoc。

第二部分：模型层

YOLOv8n-seg + P2 + HAFM + BAGS + 语义原型。

第三部分：主动学习层

VARD-AL：不确定性 + 多样性 + 稀有类别 + 模型分歧 + 标注成本。

第四部分：系统层

Vue3 + FastAPI + SQLite + ONNX Runtime。

第五部分：闭环层

预标注 → 人工修正 → 质量控制 → 数据回流 → 增量训练。

十四、最终实施顺序

  1. 第一优先级：下载并检查 PlantSeg。 确认图片、掩码、类别映射、官方划分全部正确。这是整个项目的地基。
  2. 第二优先级：训练 YOLOv8n-seg 基线。 先确保检测框和病斑掩码都能正常输出。
  3. 第三优先级：开发 HAFM 和 BAGS。 这是模型算法创新的主体。
  4. 第四优先级：实现 VARD-AL。 一定要有 Random 对照实验。
  5. 第五优先级：开发完整标注平台。 把模型、主动学习和人工修正整合起来。

最终目标不是把 YOLO 的 mAP 提高几个百分点，而是做出一个完整的数据生产闭环：

  • 模型负责自动发现病斑；
  • 主动学习负责发现最值得人工标注的图片；
  • 人工负责纠错；
  • 系统负责积累高质量标签；
  • 新模型利用这些标签持续提升。

对于1—2人团队，这条路线既有算法创新，也有企业应用价值，而且能够围绕比赛的三个最高权重评分项形成完整证据链。
