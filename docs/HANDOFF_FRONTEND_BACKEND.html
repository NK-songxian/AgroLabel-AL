接口契约（先冻结，再写代码）

来源 docs/INTERFACE.md，字段名一字不能改。先看清调用链路，再看四个接口。

方法路径入参出参
POST /api/predict {image_base64 或 image_id} {instances:[{class_id, class_name, score, polygon, bbox}], latency_ms}
POST /api/sample {pool:[image_id...], k, strategy}
strategy: random | entropy | tta | coreset		 {selected:[image_id...], reasons}
POST /api/edit-cost {pred_instances, gt_instances} {edit_count, breakdown:{新画,删实例,改类别,拖边界,标为无目标}}
GET /api/health — {status:"ok", model:"...", classes:34}
数据格式
分割标注为 YOLO seg txt：每行 class_id x1 y1 x2 y2 ...（归一化多边形）；实例字段 {class_id, class_name, score, polygon, bbox}。
时延预算
单张 /api/predict ≤ 300 ms；模型推理参考量级 20–30 ms @640（YOLOv8n-seg，以实测为准），服务层余量充足。
加载策略
模型在进程启动时加载一次，不要每次请求重复加载权重。

技术栈选型（已定，照这个做）

一句话：后端 FastAPI，前端 React + Konva。理由、备选和依赖清单都在下面，不用再纠结。

后端

Python · FastAPI

Uvicorn · Pydantic v2 · Pillow/OpenCV
  • 与模型同语言，可进程内直接调用
  • 自带 Swagger 文档 /docs
  • 异步 + 入参自动校验
前端

React 18 · TypeScript

Vite · react-konva · Zustand · Ant Design
  • Konva 画布：多边形/拖拽/缩放性能好
  • Vite 秒级启动
  • Ant Design 快速搭 UI
通信

HTTP · JSON

base64（小图）/ multipart（大图）
  • 接口契约见第 2 节
  • 前后端零耦合
  • 方便演示与抓包调试
层推荐为什么不选其他
后端框架FastAPIFlask 同步且无自动文档；Node/Go 要跨进程调 Python 模型，多一层序列化，时延和复杂度都涨
画布库KonvaFabric.js 的 React/Vue 封装较弱；原生 Canvas 要自己实现命中检测与变换，工作量大
前端框架React 18react-konva 最成熟、示例最多；若你更熟 Vue，可用 Vue3 + vue-konva 平替，其余不变
状态管理Zustand比 Redux 轻，标注状态不复杂，够用即可
打包工具ViteCRA 已停止维护、启动慢
# 后端（backend/） pip install fastapi "uvicorn[standard]" pydantic pillow opencv-python python-multipart ultralytics # 前端（frontend/）—— 用 Vite 起 React+TS 模板 npm create vite@latest . -- --template react-ts npm i react-konva konva zustand antd axios
注意
node_modules/、dist/ 已在 .gitignore 中忽略，不要提交。
备选
若团队更熟 Vue，把前端整体换成 Vue3 + Vite + vue-konva + Pinia + Element Plus，接口契约完全不变。

协作约定

六条规则，减少返工。

RULE 01

契约先行

字段名 / 路径不改；要改先发群里确认，双方同意再动。

RULE 02

Mock 先行

不要等模型，先用假 JSON 把前后端联调通，模型好了直接换。

RULE 03

分支开发

feature/backend、feature/frontend，PR 合并到 main，不直接推 main。

RULE 04

别提交垃圾

node_modules/、dist/、.env、*.pt、数据集一律不提交。

RULE 05

每天同步

当前进度 + 卡点，一句话即可，别闷头做。

RULE 06

控时延

服务层自身开销要小，别把 300ms 预算花在序列化 / base64 上。
