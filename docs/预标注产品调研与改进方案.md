## 3. 主流预标注软件怎么做

### 3.1 五家平台的技术路线

| 平台 | 模型接入 | 交互精修 | 排队/主动学习 | 质量门禁 |
|---|---|---|---|---|
| **CVAT**（MIT，自托管） | Nuclio serverless function / HF / Roboflow / CLI+SDK；不改核心即可接自建模型 | SAM 3 文本/视觉提示全图同类分割、SAM 2 跨帧传播、形状批量转换 | 产品内不闭环，靠外部编排 | GT 比对（IoU/P/R）+ Honeypots + Consensus Agreement Score + Immediate Feedback + Review Issues |
| **Label Studio**（Apache-2.0） | ML Backend SDK，只需实现 `predict()` / `fit()`，模型无关 | Interactive pre-annotations：画框当下回传正负点提示 | Enterprise 版 webhook→fit→新预测→预测分升序队列 | 30+ 一致性指标，可到“问题级”，Pairwise/Consensus 双方法论 |
| **Supervisely**（商业） | 唯一把训练内置进循环；模型链（检测器→SAM→分类器）+ 文本提示 | Smart segmentation、Label by example、文本提示 | **Live Training**：每标 2–5 张就持续微调，无重训事件，无空窗 | Job/Queue 角色权限 + Accept/Reject + Consensus/Exams/Issues |
| **Encord**（商业） | Task Agents + micro-model（1–5% 种子集） | SAM2、跟踪、跨传感器传播 | Active：acquisition function 排序 + Collections 定向标注 | IoU 一致性 + GT 准确率系数（>0.9 可接受）+ 返工率 + Workflow 状态机 |
| **V7 Darwin**（商业） | Model 工作流节点 + SAM3 文本提示 | Auto-Annotate、Auto-track（出画再入保持身份） | Model 节点 + webhook 自建 | 可视化无代码多阶段 Workflow + 条件路由 + 15+ 质量指标告警 |

### 3.2 可复核的工时证据

Supervisely 公开了**唯一带完整假设**的技术报告（10,000 图；手工 3.5min/图；SAM3 90s/图；纯审阅地板 30s/图；6h/工作日）：

| 方案 | 工作小时 | 日历天 |
|---|---|---|
| 纯手工 | 583 h | 97 d |
| SAM 3 零样本 | 250 h | 42 d |
| HITL（4 次离散重训，每次停 1 天） | 145 h | 24 d |
| **Live Training（持续训练）** | **102 h** | **17 d** |

三个关键推论：

1. **纯审阅地板 30 秒/图**是任何预标注方案的成本下限；“10× 提效”只在从零手工基线下成立。
2. 基础模型（SAM3）在最初约 10 小时比 HITL 快，但领域化模型一旦上线就反超；**领域适配比模型规模更重要**。
3. HITL 比 Live Training 多花 30–35% 工时，主要浪费在重训空窗和引导期，而不是推理本身。

CVAT 客户实践（Omdena 杂草检测）报告单图时间下降 60–80%；医疗血管分割案例为手工 36min/图 vs 修正 NN 预测 4min/图。这些数字口径不一，只作方向参考，不作为我们的承诺指标。

- Supervisely Live Training 技术报告：https://docs.supervisely.com/labeling/overview/live-training/technical-report
- CVAT 官方文档/能力说明：https://www.cvat.ai/ 、https://cvat.ai/cvat-online

## 4. AgroLabel 的指标提升路线（按优先级）

### P0：先用好现有 B6，不再追新架构

1. **B6 仍是主线**：YOLO26x-seg@1280，val mAP50 0.416 / 自写 COCOeval 0.3521。M2F-v2 0.281、SegNeXt-v2 实例 0.194、融合阴性，均已证实不如 B6。
2. **TTA / 多尺度推理**：在后端加可选 `--tta` 开关，评测 val mAP50 是否稳定提升 ≥1 个点；若提升则默认开启，若只增延迟则保留为离线精修选项。
3. **置信度校准**：统计 B6 在 val 上按 score 分箱的平均 IoU / 类别正确率，找出“高置信但错误”的区间。这是后续自动接受阈值和排队策略的基础。

### P1：用 AL 把 B6 变成“会成长的预标注器”

1. 队友跑 `m8_al.py` 的 **4 策略 × 5 轮**全量消融（官方 `yolo26x-seg.pt` 冷启动，绝不能用 B6）。
2. 对比 random / entropy / tta / coreset 在相同标注预算下的 mask mAP 曲线；选胜出策略。
3. 用胜出策略挑出的高价值样本**增量微调 B6**，再在 val/test 上评测；目标是“用 40–60% 标注量达到或接近全监督 B6”。
4. 工程上把“重训空窗”压缩：每轮结束自动触发推理与队列更新，避免 Supervisely 报告中的 HITL 空窗损耗。

### P2：点提示精修与掩码后处理

1. 后端已有 `/api/refine` 点提示；三臂 C 臂（`noprompt`）将首次给出它的**独立时间贡献**。若 C 显著慢于 B，说明点提示确实省时，应默认开启。
2. 对 B6 低置信掩码做 **SAM2 box-prompt 精修** A/B（用 B6 框作提示，只改边界不改类别）。已有 `i03_ondemand_refine.py` / `m13_box_prompt_eval.py` 可复用；判定标准：val COCOeval mAP 提升 ≥1 点且单图延迟 <300ms。
3. 长尾病斑类（small object）单独做 hard-example mining，避免被宿主大类稀释。

### P3：把人工从“画”变成“审”

1. **置信度排队**：高置信预测进入快速审阅队列，低置信/高熵进入精修队列；前端「智能选样」已支持 entropy，需补 score 阈值。
2. **批量预标注导入**：实现前端读取 `predictions_b6.json`，避免每张图现场调 142MB 模型；队友明确提到这是当前缺口。
3. **质检门禁**：移植 CVAT 的 Honeypot（隐蔽 GT 图）、Consensus（双人分歧）、Immediate Feedback（提交即打分）三件套；先用小规模 pilot 验证。
4. **指标闭环**：每次实验固定报告四元组 —— 单图中位耗时 / 加权编辑成本 / 提交质量 IoU / 达到目标 mAP 所需标注量。

## 5. 人工成本下降的量化目标

以 Supervisely 的 30 秒/图纯审阅地板为参照，设定三阶段目标：

| 阶段 | 目标 | 验证方式 |
|---|---|---|
| 当前基线 | 测出 A/B/C 三臂真实中位耗时 | 三臂实验 v2 包 + 后端 ops 日志 |
| 短期（B 臂优化） | B 臂耗时 ≤ A 臂的 50%；加权编辑成本下降 ≥40% | `human_stats.py --with-editcost` |
| 中期（AL + 排队） | 达到同等 mAP 所需标注量下降 ≥30% | `m8_al.py` 4 策略曲线 |
| 长期（Live 化） | 单图耗时逼近 30–60s 审阅区间；重训空窗 ≈0 | 持续训练 + 自动队列更新 |

> 这些是**目标区间**，不是已实现结果。所有数字必须由三臂实验和 AL 消融回传后计算，禁止用厂商宣传倍数代替自有证据。

## 6. 软件著作权切入点

软著保护的是**代码表达与工程实现**，不保护算法思想本身。建议以“系统 + 方法”组合登记，突出可运行的工程闭环：

**建议名称**：`AgroLabel 智慧农业多模态预标注与主动学习系统 V1.0`

**可登记的四个功能模块**：

1. **多源影像预标注模块**：YOLO26x-seg 批量推理 → COCO/YOLO 双格式预标注 → 置信度与类别写回；
2. **交互式精修与编辑成本计量模块**：点提示精修、增/删/拖/改四类操作自动计数、加权编辑成本计算；
3. **主动学习排队与增量训练模块**：entropy / TTA / coreset / random 四策略采样、冷启动权重保护、每轮 test 评估与权重传递；
4. **质量门禁与统计模块**：Honeypot GT 注入、Consensus 分歧标记、双计时口径、按人/按臂效率汇总。

**登记材料建议**：

- 源代码：前端（Vite/React）、后端（FastAPI 路由）、`m8_al.py`、评测与可视化脚本，按“前后端合计 60 页”常规要求整理；
- 文档：软件设计说明书 + 用户手册（三臂实验协议可直接作为“典型应用场景”章节）；
- 创新点措辞聚焦工程流程：“一种面向植物病斑实例的置信度驱动预标注与交互式精修方法”，避免使用“首创/国际领先”等无法证明的表述；
- 模型权重不必作为软著登记客体，但可在说明书中作为系统依赖资源描述。
