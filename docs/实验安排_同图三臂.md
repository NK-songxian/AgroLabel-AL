# 三臂标注效率实验 · 实验安排（同图三臂 × 4 组）

> 版本 v2.0 · 2026-11-24
> 取代 v1.1 的「一图一臂」协议（那份是每类 2 张、分给 2 个臂，三臂比的是不同图，类别构成对不上）。
> 本文只讲**怎么做**；接口与代码见 `backend/README.md`、`docs/INTERFACE_ADDENDUM.md`。

---

## 一、要回答的三个问题

| # | 问题 | 对比 | 数据 |
|---|---|---|---|
| Q1 | 预标注到底省不省人工？ | assisted − manual | 同图配对，32 组 |
| Q2 | 点提示（交互式精修）本身有没有用？ | assisted − noprompt | 同图配对，32 组 |
| Q3 | 换一批图结论还成立吗？ | 组间一致性 | g1..g4，各 8 图 |

**核心设计：同一张图在三个臂各标一遍。** 图难度被完全消掉，每张图给出一个配对差
`d = cost(臂A) − cost(臂B)`。这比"不同图跨臂比"稳一个量级。

## 二、设计参数

```
x = 8 张/组      G = 4 组      总任务 = 8 × 3 × 4 = 96
图数 = 32 张（同一张图被三个臂各标一次）
每臂任务数 = 32（三个臂完全等量）
```

- **抽样**：从 val 846 张里随机抽 32 张（不放回，组间不重图），seed = `20261124`，可复现
- **臂顺序轮转**：每张图的三个任务按 `(组号 + 组内序号) mod 3` 旋转起始臂，
  三个臂在"第 1/2/3 遍"上各占 10–11 次 → 熟练效应被摊平，不会偏爱某个臂
- **执行顺序：臂优先（按臂分块）** —— 一组内先把某个臂的图全部做完，再切下一个臂，
  符合实际标注习惯。臂内部图序随机，避免"先做的图更仔细"
- **臂顺序按组轮转**：`g1: A→M→N`、`g2: M→N→A`、`g3: N→A→M`、`g4: A→M→N`。
  这样三个臂在"第 1/2/3 个做"上分布均衡（G=4 时 assisted 两次居首、另两个各一次；
  **G 取 3 的倍数时三臂完全均等**），块顺序效应才可被估计
- **组越多越好**：G 从 4 加到 6 或 8，标注量线性增长（24 任务/组），
  组间方差估得更稳 —— 想加大就重跑一次生成器改 `--groups`
- **类别覆盖**：随机抽样落到 17 个宿主类（其中 10 个类只出现 1 张）。
  这是随机的代价；如果要严格覆盖 34 类，需改成按类分层抽（另说）

> 想减量：`x=6, G=4` → 72 个任务（约 1.5 h）。
> 想增量：`x=10, G=4` → 120 个任务。

## 四、两种模式怎么分

| | 普通标注模式（打开网页就是） | 实验模式（点左下角按钮进入） |
|---|---|---|
| 预标注 | 自动加载 | 跟随任务：assisted / noprompt 有，manual 没有 |
| 点提示 | **可用** | 只有 `noprompt` 臂禁用 |
| 臂选择 | **不出现**（无需选，默认落 `out/annotations/assisted/`） | 出现「切到臂」下拉框 |
| 队列 | 全部图 / 按 split | 清单里的 96 个任务 |
| 用途 | 自由标注、演示、试工具 | 产出三臂实验数据 |

**实验模式里"选臂"= 跳到该臂的下一个未完成任务**，而不是直接改臂 ——
臂始终跟着任务走，产物不可能落到错的 `out/annotations/<arm>/`。

队列本身已经按臂分好块了，所以正常流程是：

```
8 张 assisted  →  8 张 manual  →  8 张 noprompt   （g1）
然后自动进入 g2，臂顺序轮换成 manual → noprompt → assisted
```

一个臂的 8 张做完后，按 `→` 会自动进入下一个臂（右栏臂标签随之变化）。
想提前切到别的臂，就用面板里的「切到臂」下拉框跳过去。

退出实验模式后，臂自动复位成「预标 + 点提示」，点提示立刻恢复可用。

## 五、操作流程（每个任务）

1. 在左栏点下一个任务（或按 `→`）。**臂跟着任务自动切换**，不需要手动选；
   一个臂的 8 张做完后，下一个任务就进入下一个臂的块。
2. 按该臂的条件标：
   - **预标 + 点提示**：B6 预标注已加载 → 修正（删误检/补漏/拖顶点/改类）→ 提交。
     「点提示」可用：点一下可疑处让模型重新描一片。
   - **纯人工（无预标注）**：空白画布 → 从零画多边形 + 选类 → 提交。
   - **预标 · 禁用点提示**：同第一个臂，但**点提示按钮禁用**（按 `P` 也会被拒）。
3. 「提交并下一张」= 该任务完成，自动翻到下一个。

**禁止事项**（违反则这条数据作废）：

- ❌ 打开 `gt_labels_val/` 或任何 GT 文件对答案
- ❌ 手动切换实验臂（实验模式下本来也切不动）
- ❌ 中途换标注员（一个人的肌肉记忆是他的特征）
- ❌ 跳过某个任务去标后面的（顺序是随机交错设计的）

## 六、计时口径（不用手记，程序自动落盘）

每个任务提交时写进 `out/annotations/<arm>/<image_id>.json`：

| 字段 | 区间 | 用途 |
|---|---|---|
| **`elapsed_from_open_ms`** | 打开这张图 → 提交 | **主口径**（含看图/判断） |
| `elapsed_ms` | 图上第一个标注动作 → 提交 | 辅助口径（只算动手） |

- 两个都报，主用 `elapsed_from_open_ms`（协议 §3 口径）
- 走神/离开：不必手动暂停，事后按规则剔除（>15 min 视为离开）
- `timing_sheet.csv` **留空即可**，只在异常时写备注

## 七、熟练效应：不能"忽略"，但方向对我们有利

同一人同一图第 2、3 遍一定更快（病灶位置记住了）。这**不是随机误差，是系统性的顺序效应**。

已经做的控制：

1. **臂顺序轮转** —— 三个臂在"第 1/2/3 遍"上分布均衡（10–11 次）
2. **随机交错** —— 同一张图的三遍之间隔着别的图
3. **多组** —— 4 组各自独立，可估"换图后结论稳不稳"

诚实结论（写进报告）：

> 熟练效应会**压缩**臂间差异，因此本实验测得的预标注收益是**保守估计**。
> 顺序已随机化，并用"第几遍"作为协变量做了稳健性检查。

这一句反而是加分项：它说明我们知道自己在测什么。

## 八、数据分析计划

### 7.1 主分析：同图配对

对每张图 `i` 和每对臂 `(A,B)`：

```
d_i = elapsed(A, i) − elapsed(B, i)        （毫秒）
```

- 每对臂 **32 个配对**（4 组 × 8 图）
- 用 **Wilcoxon 符号秩检验**（不假设正态）+ 报中位差与 95% CI（bootstrap）
- 同时报"每臂中位耗时"作为描述性数字（但**主结论看配对差**）

### 7.2 组间一致性

按 4 组各算一次配对中位差，看方向是否一致 → 回答 Q3。

### 7.3 编辑成本（第二指标）

```powershell
python src/m6_editcost.py ... --labels-dir out/annotations/<arm> --weight-preset realistic
python backend/tools/human_stats.py --with-editcost --paired
```

- 权重口径用 **realistic**（新画 1.0 / 删 0.15 / 改类 0.15 / 拖边 0.3 / 无目标 0.15），
  与手册 §08 的 7.63 / 5.94 可比（详见 `docs/编辑成本权重_冲突与实施建议.md`）
- `proto`（协议旧稿那套 0.5/0.8/0.3）只作敏感性分析，不作主口径

### 7.4 块顺序效应（臂优先带来的）

臂优先把"第几遍"和"是哪个臂"绑在了一起。处理方式：

1. **靠组轮转拆开**：4 组里三个臂各居首 1–2 次，块位置与臂不完全共线
2. 分析时把 `组` 与 `块位置（1/2/3）` 作为协变量报一次稳健性，
   看扣掉块位置后配对差的方向是否不变
3. G 取 3 的倍数（6、9）时三臂完全均衡，是最干净的做法

只要方向在两种处理下一致，就说明收益不是顺序造成的。

### 7.5 报告要给的四个数

| 指标 | 形式 |
|---|---|
| Q1 时间节省 | 中位配对差 + 百分比 + IQR |
| Q1 编辑量节省 | `weighted_per_image` 差值 |
| Q2 点提示贡献 | assisted − noprompt 的配对差（若为正，说明点提示省时间） |
| Q3 稳健性 | 4 组各自的方向 + 顺序协变量检查 |

## 九、数据卫生（这几条踩过坑）

1. **一个任务只提交一次**。同一 (图, 臂) 再提交会**覆盖**前一次的耗时（`out/annotations/<arm>/` 按图存一份）。改错了就改完再提交，别"先提交一次试试"。
2. **实验模式下臂是锁定的**。要改臂只能在非实验模式（左下角面板里那个下拉框）。
3. **中途休息不要停服务**，关浏览器不影响：进度落在磁盘上，重开浏览器 → 实验模式 → 读清单，会显示"已完成 N/96"，队列会自动标✓。
4. **别在实验中途改清单**（改 x/G/seed 会让已完成任务的归属对不上）。
5. 跑完先把 `out/annotations/` 和 `out/logs/` 整个复制一份再分析。
6. **多人：每人一套不重叠的图**。落盘路径是 `out/annotations/<arm>/<image_id>.json`，
   只按臂分目录 —— 两个人标同一张图的同一个臂会**互相覆盖**。
   做法（`--persons` 会从同一抽样里切出不重叠的片）：
   ```powershell
   # 第 1 人
   python backend/tools/make_experiment_manifest.py --data ... --x 8 --groups 4 `
       --persons 2 --person 1 --out out/experiment/p1.json
   # 第 2 人
   python backend/tools/make_experiment_manifest.py --data ... --x 8 --groups 4 `
       --persons 2 --person 2 --out out/experiment/p2.json
   ```
   各自把自己的清单指给后端：`$env:AGROLABEL_EXPERIMENT = "out/experiment/p1.json"`。
   实测两份清单**重叠 0 张**。姓名填在顶栏「标注员」框里，会写进每张的 sidecar，
   `human_stats.py` 按 operator 分组统计。

## 十、试点：先做 1 组再决定

96 个任务一次做完有风险（发现设计问题就晚了）。建议：

1. 先做完 **g1 的 24 个任务**（约 20–30 分钟）
2. 立刻看数据：`python backend/tools/human_stats.py --paired`
3. 如果同图三臂的耗时差**稳定**（同一张图三个臂的相对关系一致）→ 继续 g2–g4
4. 如果差得很乱 → 停下来查原因（工具？预标注质量？口径？），再决定是否继续

这一步成本很低，能省掉 3/4 的返工。

## 十二、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 熟练效应压缩差异 | 收益被低估 | 已轮转 + 交错；报告如实说明（偏保守方向） |
| 32 张图类别覆盖不均（17 类，10 类仅 1 张） | 结论偏"这几类" | 报告写明抽样方式；如需全覆盖改分层抽样 |
| 单人标注 | 结论仅对该标注员 | 报告限定；有第二人则每人一套，人作为组间因素 |
| 中途工具出问题 | 时间记录污染 | 剔除异常（>15 min / MAD 离群），并记录剔除数量 |
| 同图重复标注导致"记得答案" | 一致性偏高 | 同臂不重复标；三臂之间是不同条件，不算重复 |
